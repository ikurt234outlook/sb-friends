# 饼友：烧饼站好友增强插件

状态：0.1.1 MVP 已实现，2026-11-06。本文说明当前实现及其设计依据；使用方法见 [README](../README.md)，证据和未验证项见 [验收记录](饼友-MVP验收.md)。源码、文档和安装包统一放在 `codex-dev/`。

## 用户的使用过程

在烧饼站发现值得继续关注的人，在其主页点「加入饼友」，写一条备注并归入分组；下次打开侧栏集中阅读这些人的主题和回帖摘要。名单属于浏览器本地配置，不改变站内关注关系，不要求对方安装扩展。

当前功能：个人页及 UID／主页链接添加；备注、分组、置顶和移除；列表搜索；动态按用户／分组／类型筛选；手动刷新、停止和更早分页；JSON 备份导出导入；原站昵称旁的轻量标记与悬停备注。Chrome／Edge 使用同一 MV3 构建。

后续优先级保持为简单关键词筛选 → 低频自动刷新及通知 → Firefox → 按实际需要决定云备份。首版不含自动发帖、回复、点赞、积分业务、云同步或 Telegram。

## 站点证据和适配规则

| 观察 | 采用的规则 |
| --- | --- |
| 用户链接为 `/user/{UID}`，个人页含 `.user-header .user-name` | UID 为主键，展示名只用于呈现；改名不改变备注关联 |
| `?tab=topics` 是主题，`?tab=replies` 是回帖 | 两种类型分别读取、记录成功时间和错误 |
| 列表使用 `li.post-item`、`a.post-title`、`.post-meta` | 集中在 `src/site/sb/parser.ts` 解析 |
| 回帖摘要为 `.profile-reply-excerpt`，定位链接带 `replyid` | 回帖键为 `reply:{topicId}:{replyId}`，保留原站定位链接 |
| 回帖条目头像和用户链接可能属于主题作者 | 行为人取已验证主页 UID，另存 `topicAuthorUserId` |
| 列表时间有 `data-performance-time`，详情页只有 `.post-time` 相对时间 | 转换 Unix 秒并标为「原站」；不能声称已确认精确创建时间，更不能解释为最后在线 |
| 评论数位于评论图标所在 span，最后回复人也可能是数字昵称 | 识别评论 SVG 后读数，不扫描所有数字取最后一项 |
| 页面有“下一页”链接 | 检查同站、同 UID、同类型后记录下一页；只在用户点击后加载 |
| 访客可见个人页回帖摘要，但主题详情评论需登录 | 读取个人页公开摘要，不依赖受限评论详情 |
| `/user/1.json` 曾返回 404 | 不假设 Discourse JSON API；不据此推断站点没有其他 API |
| OAuth 公告及应用接入存在 | 登录接入不等于公开动态 API，首版不依赖它 |

证据入口：[UID 1 主题](https://linux.sb/user/1?tab=topics)、[UID 1 回帖](https://linux.sb/user/1?tab=replies)、[UID 31718 回帖](https://linux.sb/user/31718?tab=replies)、[OAuth 公告](https://linux.sb/topic/29958)。

典型归属案例：UID 1 回帖页中，主题 30149、回帖 297507 的头像指向 UID 31718；后者是主题作者，回帖行为人仍为 UID 1。解析测试专门覆盖这一差异。

## 技术结构

TypeScript + React + Jotai + Vite / esbuild，Node.js 22 及以上。本次使用 Node.js 24.22.1。Windows PowerShell 可以直接运行 npm 命令。

```text
src/
  background/main.ts      # 消息入口、串行刷新队列、停止和冷却
  background/store.ts     # chrome.storage.local 单一写入者
  site/sb/parser.ts       # 用户资料、主题、回帖、分页、页面分类
  site/sb/request.ts      # 页面内同源请求、HTTP 分类
  content/main.ts         # 原站按钮、标记、DOM 读取消息
  domain/state.ts         # 名单更新、缓存合并、备份规则
  domain/friendNote.ts    # 备注规范化
  shared/                 # UID/URL 规则及类型
  ui/                     # 侧栏和选项页
scripts/
  build.mjs               # manifest、UI、service worker、content script
  package.mjs             # ZIP
  browser-check.mjs       # 独立配置中的浏览器验收
  browser-helpers.mjs     # 浏览器路径与测试生命周期
public/icon.svg           # 原创饼友图标
```

状态流：侧栏或页面发命令 → 后台验证 → 同站 content script 请求 HTML → DOMParser 提取规范对象 → 后台统一写入 → storage 变更同步 UI 与页面标记。不会将获取的 HTML 注入原网页执行。

service worker 与 UI 的普通消息使用 `sb-app` 通道，页面读取使用 `sb-page`；不接受任意站外 URL。解析器与业务状态分离，原站页面变化时主要修复适配器和回归样本。

## 数据含义与一致性

完整接口见 `src/shared/types.ts`。

- `Friend`：UID、展示名、头像 URL、80 字备注、最多 10 个分组、置顶、加入／更新时间。
- `Activity`：稳定 ID、行为人 UID、主题作者 UID、类型、标题、500 字摘要、主题／回帖 ID、URL、版块、原站列表时间、主题回复数、刷新时间和新发现标记。
- `Scope`：按 UID + 类型记录最近成功、最新第一页成功时间、下一页、错误和已观察的浏览账号标识。
- `Job`：本轮 ID、状态、总数、完成数、当前用户与错误。
- `Backup`：固定 `site: linux.sb`、schemaVersion 1、导出时间与名单；不包含动态或站点会话。

后台串行提交写入。刷新只合并资料和动态，不覆盖正在编辑的备注。任务保存用户加入时的 generation；用户移除或重新加入后，旧任务不能恢复旧记录。

缓存按稳定 ID 去重；最近一页没出现旧条目不代表内容被删除。首次取得数据不标新发现，后续最新页的新 ID 才标记；加载历史页不标新发现，也不延长最新页缓存。

最近 30 天、每人 100 条、全局 2000 条的限制在合并时执行。头像只保留原站 URL，备注和关系独立于可清理的动态。额度失败优先清除缓存、保存名单并停止操作。名单上限 200 人。

导入先校验站点、版本、UID 唯一性和字段上限，显示新增／冲突；默认保留已有条目，显式勾选才覆盖备注、分组与置顶。不同站点不按昵称混合。

## 请求、失败和停止

1. 用户触发预览、刷新或分页后，后台选已有烧饼站标签页，让 content script 同源 GET HTML。已在真实 MV3 扩展访客模式验证，不创建隐藏采集标签页。
2. 无标签页时提示用户打开站点；页面失联时提示刷新原站。
3. 同一全局队列串行执行，请求开始间隔至少 2 秒。最新页成功 5 分钟内且观察账号一致可复用，历史页独立计时。
4. 主题和回帖各自提交结果。失败时停止本轮，已完成类型保存，未完成类型保留旧缓存；不自动重试。
5. 429 采用 Retry-After，缺失时 10 分钟；403／验证拒绝停止并提示原站处理。
6. 页面请求 20 秒超时，后台 25 秒兜底。停止通过 AbortController 和任务状态拦截；迟到结果不写回。
7. worker 重启后将遗留 running 标为中断；用户重新刷新继续。页面关闭导致读取失败并保留已完成数据。

20 人同时刷新两类数据需 40 次请求，按 2 秒起始间隔至少约 78 秒。界面显示进度与停止按钮，不承诺即时全量历史。

## 界面和权限

侧栏只有「饼友」「动态」两页签，设置放在齿轮入口。名单支持搜索和分组，动态提供用户／类型筛选。空名单有添加引导，导入有预览，错误显示在相关操作附近。

沿用紧凑文字列表，柔和绿色强调添加与刷新，主题跟随系统；360px 和 480px 渲染已检查。动态按批次显示缓存条目，切页保留当前会话滚动位置。页面入口优先放原站导航，找不到导航时显示固定按钮。

权限仅 storage、sidePanel、`https://linux.sb/*`。无 cookies、alarms 或通知权限，无后端、代理转发或遥测。隐私说明见 [隐私说明](隐私说明.md)。
